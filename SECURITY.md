# Seguridad y reporte privado

No incluir datos de socios, contraseñas, tokens, respaldos ni cadenas de conexión en issues públicos. Usar el reporte privado de vulnerabilidades de GitHub si el propietario lo habilita; en caso contrario acordar un canal privado con el propietario.

Incluir versión, condiciones necesarias, pasos con datos sintéticos e impacto. No se garantizan tiempos de respuesta ni se declara una certificación de seguridad. Ver AUDITORIA-SEGURIDAD.md y AUDITORIA-PRIVACIDAD.md antes de distribuir una versión.

Si se expone una credencial, revocarla primero en su proveedor. Limpiar el árbol o reescribir Git no invalida secretos ya copiados. La reescritura tampoco borra forks, clones o cachés de terceros.
